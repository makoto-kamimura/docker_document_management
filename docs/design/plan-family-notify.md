# 計画: 家族で紙の情報を共有・通知する（撮影 → OCR → 解析 → 通知 → 確認 → 対応）

## ねらい

**家に届いた紙を、家族みんなで見逃さない。**

OCR・全文検索は裏側の基盤とし、表側の価値を「家に届いた重要な情報を、家族が見逃さない」に置く。
学校のプリント・請求書・役所の通知などを撮影すると、内容から**重要度と期限**を判定し、
家族に**通知**する。誰が確認して誰がまだかを共有し、**全員が確認したらリマインドを止める**。

```text
📷 撮影 → OCR → 文書解析（重要度/期限/対象/キーワード）→ 通知
        → 家族が確認（未読/既読・対応状況）→ 対応状況を共有 → 全員確認で通知終了
```

## 前提（既存機能の流用）

| 要素 | 流用したもの |
|---|---|
| 家族 | 既存の**グループ**（同じグループのメンバーは書類を自動で閲覧できる, F-36） |
| 既読 | 既存の既読記録 (F-32)。詳細/ビューアを開いた時点で記録 |
| 権限 | 既存の ACL。家族 = 所有者 + 同じグループのメンバー + 個別共有先 |

DB マイグレーション基盤が無いため（`create_all` 運用）、**既存テーブルは変更せず新規テーブルのみ**追加する。

## 実装

### 1. 文書解析（`app/backend/app/services/analyze.py`）

OCR テキストからルールベースで抽出する。**外部サービスに本文を送らない**（家庭の書類のため）。

| 項目 | 判定 |
|---|---|
| 期限 | 「9月30日までに」「提出期限 令和8年9月30日」「2026/10/31 納期限」など。日付の前後に締切語があるもの。年の無い日付は受け取り日から見て直近の将来として解釈 |
| 行事日 | 「10月5日(日)に開催」など、日付の前後に開催・実施・日程などがあるもの |
| 重要度 | high: 重要/至急/必ず/督促/未納 などの語、または「期限 + 提出/支払い/申込/手続き」。low: セール/キャンペーン等で期限なし。それ以外 normal |
| 対象 | 「保護者の方へ」「山田太郎 様」など（宛名 → 対象語の順で判定） |
| キーワード | 提出 / 支払い / 申込 / 出欠 / 持ち物 / 手続き / イベント |
| 分類 | 学校 / 支払い・請求 / 行政 / 医療 / 地域 / 契約・保険（カテゴリ未設定時に採用） |
| タイトル候補 | 自動命名（`資料_1757…`）のときだけ、見出し行に置き換える |

漢数字（令和八年四月一日）、OCR が入れた空白（`2026 年 9 月 15 日`）にも対応する。

### 2. データモデル（`app/backend/app/models/family.py`）

| テーブル | 内容 |
|---|---|
| `document_insights` | 解析結果（重要度・期限・行事日・対象・キーワード・判定理由）。`manual` が立つと自動解析で上書きしない。`notified` で初回通知の重複を防ぐ |
| `document_actions` | 家族それぞれの対応状況（確認した / 対応する / 対応済み / あとで確認） |
| `document_comments` | 家族間のコメント |
| `notifications` | アプリ内通知（受信者ごと。新しい紙 / リマインド / 再通知 / 期限 / コメント） |
| `push_tokens` | 端末の Expo Push Token |

**確認済みの定義**: 「あとで確認」以外の対応を選んだ人、または書類を開いた（既読）人。
「あとで確認」は未確認のままとし、リマインドを続ける。

### 3. 通知エンジン（`app/backend/app/services/family.py` / `push.py`）

- **初回通知**: OCR と解析が終わった時点で、登録者以外の家族へ1回だけ。
- **リマインド**: 重要 or 期限つきの書類で未確認の家族へ `REMINDER_INTERVAL_HOURS`（既定24時間）ごと、
  最大 `REMINDER_MAX_COUNT`（既定3回）。**全員が確認したら止まる**。期限切れでも止まる。
- **期限通知**: 期限の `DEADLINE_NOTICE_DAYS`（既定1日）前に1回。「対応する」を選んだ人がいればその人へ、
  誰かが「対応済み」なら送らない、どちらも無ければ家族全員へ。
- **もう一度通知**: 家族の誰でも、未確認の人を指名して（または未確認の全員へ）送れる。連打は5分間抑止。
- **コメント通知**: コメントを書くと他の家族へ。
- 判定と送信は OCR ワーカーのループで10分ごとに実行する（`REMINDER_INTERVAL_SEC`）。

**プッシュ通知**: Expo Push API に送る。Expo/Apple/Google のサーバーを経由するため、
**本文に書類の中身を含めない**（「新しい紙が届きました」等の定型文 + `document_id` のみ）。
端末が Expo Push Token を登録したときだけ送られ、未登録ならアプリ内通知だけで動く。

### 4. API

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/documents/{id}/family` | 解析結果 + 家族それぞれの既読・対応状況 |
| PUT | `/documents/{id}/insight` | 重要度・期限・対象の手動修正（編集権限。以後 自動解析で上書きしない） |
| PUT | `/documents/{id}/action` | 自分の対応状況を記録（同時に既読化） |
| POST | `/documents/{id}/notify` | もう一度通知（`user_id` 未指定なら未確認の全員） |
| GET/POST | `/documents/{id}/comments` | コメントの取得・追加 |
| GET | `/notifications` `/notifications/unread-count` | 自分宛ての通知・未読数 |
| POST | `/notifications/{id}/read` `/notifications/read-all` | 既読化 |
| POST/DELETE | `/push-tokens` | 端末トークンの登録・解除 |

一覧 `GET /documents` の各件に `importance` / `deadline` / `event_date` / `audience` / `keywords` /
`my_action` / `family_total` / `family_confirmed` を追加した。

### 5. 画面（モバイル / Web 共通の構成）

- **一覧**: すべて / 未読 / 🔴重要 / 📅期限あり / 既読 のタブ。各行に重要バッジ・期限（3日以内は赤、
  期限切れは灰）・「家族 2/3 確認」。
- **詳細（モバイル）/ 家族・対応モーダル（Web）**: 解析結果 → 自分の対応（4ボタン）→
  家族の確認状況（未確認の人に「もう一度通知」、全員向けボタン）→ コメント。
- **お知らせ**: 通知一覧（未読は色帯）。タップで対象の書類へ。モバイルはヘッダーの🔔にバッジ、
  Web はサイドバーにバッジ（30秒ごと更新）。
- **編集（Web）**: 重要度・期限・対象を手動修正できる。

## 確認済みの動作

- 合成した学校のプリント写真を実際にアップロード → 本物の OCR ワーカーで処理 →
  タイトルが「運動会の出欠についてのお願い」に置き換わり、重要度=重要 / 期限=9/30 / 日程=10/5 /
  対象=保護者 / 分類=学校 を抽出 → 家族2人に通知。
- 「あとで確認」は未確認のまま、24時間後に未確認の人だけへリマインド、全員確認で停止、
  期限前通知は「対応する」の人だけ、手動修正は自動解析で上書きされない（結合テストで確認）。
- Web 画面: 一覧のバッジ、家族・対応モーダル、お知らせ、閲覧で既読化 → 家族の確認状況へ反映。

## 未対応・今後

- 解析は日本語のルールベース。表や手書きの多い書類では期限を拾えないことがある（Web の編集画面で手直しできる）。
- プッシュの実機動作は EAS の projectId 設定が必要（`app/mobile/README.md`）。
- 「対応する人を指名する」「期限のカレンダー表示」「家族ごとの通知時間帯設定」は未実装。
