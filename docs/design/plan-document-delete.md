# 計画: 登録した書類の削除（完全削除）（2026-11-09）

> 実装前の計画の記録。仕様の正は [README.md](../../README.md)（5章・F-29・F-37・17.8・19章・D18・Q9）。

## Context

- 書類を削除する API と画面が無かった。F-29（削除ログ）と F-37（削除の権限）は「削除 API が無いため未適用」、未決事項 Q9 は「論理削除 / 物理削除」のままだった。
- 要望: 登録した書類を削除できるようにする。
- 確認済みの方針: **完全に削除する**（元に戻せない。ゴミ箱は設けない）。DB の行、保存先のファイル、検索索引、コメント・通知・既読・家族の対応、その書類の閲覧ログをまとめて消し、削除の記録も残さない（D18）。
- 論理削除（ゴミ箱）を選ばなかった理由:
  - 復元の画面が必要になる。
  - ゴミ箱の中の書類があると、カテゴリ・テナント・保存先の削除が外部キーで止まる。
  - ワーカー・リマインドからも除外する必要がある。
  - 家庭での利用では変更範囲に見合わない。
- 削除できる人: 所有者・管理者・「削除可」を付与された人。既存の `PermissionLevel.delete` / `deps.can_access` をそのまま使うので、公開範囲の上限も効く。

## A. API（`DELETE /documents/{id}`、204）

- 見えなければ 404、見えるが削除の権限が無ければ 403（`ensure_can_access(..., delete)`）。
- 書類を参照する表の行を明示的に消してから書類の行を消し、commit する。
  - 対象: `document_tags`・`document_versions`・`access_logs`（この3表は ON DELETE CASCADE が無い）、`document_permissions`・`document_read_receipts`・`document_insights`・`document_actions`・`document_comments`・`notifications`。
  - SQLite のテストでも同じ動きになるよう、カスケードには頼らない。
- commit の後で、保存先の `{id}/` 配下（全ページ・処理済みページ・プレビュー・PDF・旧版）と検索索引を消す。
  - ファイルを消せなくても削除は成功させる（DB に無い書類のファイルは読まれない）。
  - 保存先に届かない書類を消せないままにすると、その保存先も削除できなくなるため。
- 応答の `can_delete`（一覧・詳細）: 自分に付与された権限を1回でまとめて取り、所有者・管理者・`delete` の付与 で判定する。返す書類は閲覧できると確認済みなので、`can_access(..., delete)` と同じ結果になる。

## B. OCR ワーカー

- 以前は、処理中に書類の行が消えると、状態の commit と失敗時の commit の両方で例外が出て、ワーカーが止まっていた。
- 処理の最初に書類の ID を取っておく。
- 失敗時: 行が無ければ何もせずに終える（`failed` にしない、通知もしない）。
- 成功時: 成果物を書いた後に行が無ければ、書いた成果物を消して終える。削除 API がファイルを一覧した後にワーカーが書き込んだ場合の取り残しを防ぐ。
- ループの `process_pending` を `try/except` で囲み、想定外の例外で OCR 全体が止まらないようにする。

## C. Web

- 一覧の行の操作ボタンに、`can_delete` のときゴミ箱を出す。
- ビューアにも、削除できる人にだけ「削除」を出す（サムネイル表示には行ボタンが無いため）。
- `window.confirm` で確認してから消し、一覧から除く。

## D. モバイル

- 書類詳細の「保存・共有」の下に、`can_delete` のとき「この書類を削除」の行を置く。
- `Alert.alert`（削除は destructive）で確認してから消し、開く前の一覧へ戻る。一覧・お知らせはフォーカス時に読み直すので、そのまま反映される。

## 検証

- `tests/test_document_delete.py`:
  - 所有者が削除すると、関連する行・ファイル・索引が消え、ほかの書類のファイルは残る。
  - 権限: 閲覧のみ・`edit` の付与は 403、`delete` の付与は 204。管理者は「本人だけ」の書類なら 404、ほかは 204。別テナントは 404。
  - `can_delete` が正しく付く。
  - 保存先に届かなくても削除できる。
  - ワーカーの処理中に削除されても止まらず、成果物も残らない。
- Web・モバイルの型チェック。
- モバイルの実機確認は、公開デモへの反映後に行う。
