## フェーズ3: ドキュメント化・OCR・保存 ★ ◎

- [x] T-301 複数ページを単一ドキュメント(PDF)へ変換 (F-12)（複数ページ→img2pdf→ocrmypdfで1つの検索可能PDFに統合）
- [x] T-302 OCRワーカー基盤（非同期ジョブ）構築（pending→processing→done/failed のポーリングワーカー。成果物保存と本処理を分離し例外時はfailed。本番はキュー化推奨）
- [x] T-303 OCRによるテキスト抽出 (F-13)（ocrmypdf sidecar で全ページ抽出→DB ocr_text・検索索引へ。**抽出後に NFKC正規化＋CJK間の余分な空白除去で品質向上**。**OCR認識文字を集約した全文PDF出力 `GET /documents/{id}/ocr-pdf` を追加**[Web/モバイル]）
- [x] T-304 日本語（縦書き含む）・英数字混在の認識対応 (F-15)（`ocr_lang=jpn+jpn_vert+eng`、縦書き traineddata 導入済）
- [x] T-305 検索可能PDF（テキスト埋め込み）生成 (F-14)（ocrmypdfで撮影後に自動生成しMinIO保存、取得API・モバイル保存ボタンまで実装/検証済。**精度向上: deskew/rotate(osd)/clean(unpaper)/LSTM(oem=1) を適用、未対応環境は自動フォールバック**）
- [x] T-306 メタデータ付与（タイトル/登録者/登録日/タグ/カテゴリ/書類種別） (F-17)（別テーブル DocumentTag + `PATCH /documents/{id}` でタグ/カテゴリ/書類種別を編集、Web編集UI、索引反映）
- [不要] T-307 フォルダ/カテゴリによる階層管理 (F-18)
- [x] T-308 機密度判定によるハイブリッドストレージ振り分け保存 (F-20)（`storage.resolve_location`: confidential→onprem / 他→cloud。アップロード/バージョン更新時に適用、機密度変更で保存先再判定）
- [x] T-309 OCR結果の確認・手動修正UI (F-16)（`PATCH /documents/{id}` の ocr_text 更新→再索引、Web編集モーダルにテキスト修正欄）○
- [x] T-310 バージョン管理（差し替え時の履歴保持） (F-19)（DocumentVersion テーブル + `POST/GET /documents/{id}/versions`。現行を履歴退避→version++→再OCR、Web履歴UI。基本実装）○

- [x] T-408 検索結果のハイライト・該当箇所ジャンプ (F-25)（OCR本文/要約のハイライト断片と一致箇所[本文/要約/タイトル]を返却・表示）○
- [x] T-409 要約電子資料PDF出力（OCRテキスト→Dify要約→PDF生成・共有）（ワーカーが要約を生成・保存し検索/PDFで再利用。要約PDF取得API・モバイル共有まで実装/検証済。**精度向上: Dify未設定時は kuromoji 形態素解析の頻度ベース抽出要約**[先頭数文方式から改善]）
