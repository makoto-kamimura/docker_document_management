> 本書は [document_management_system_requirements.md](../document_management_system_requirements.md) の要件定義を基に、要件・システム構成・仕様を再整理したものである。実装タスクは [task.md](task.md) を参照。

## 1. システム概要

スマートフォン/タブレットアプリで紙媒体の資料を撮影し、OCRにより検索可能なドキュメントとして電子保存し、閲覧記録を管理するシステム。

| 項目 | 内容 |
|---|---|
| 利用環境 | ハイブリッド構成（オンプレミス + クラウド） |
| 重点領域 | ① OCR・全文検索　② 撮影・画質の使いやすさ |
| 主要利用者 | 撮影/登録者、閲覧者、システム管理者 |
| 提供形態 | モバイルアプリ（撮影・閲覧）+ Webアプリ（管理・検索） |

### 1.1 設計上の重点ポイント

- **画質**: 文字可読性を担保する解像度（目安 300dpi 相当以上）を維持し、OCR精度向上のための前処理（二値化・ノイズ除去）を撮影段階で実施する。
- **全文検索**: OCRテキストを検索インデックスに格納し、表記ゆれ・あいまい検索に対応。大量ドキュメント時でも実用的な検索レスポンスを維持する。
- **ハイブリッド配置**: 機密度に応じてオンプレミス/クラウドへデータを振り分ける。

### 4.2 構成要素

| レイヤ | コンポーネント | 役割 |
|---|---|---|
| クライアント | モバイルアプリ | 撮影、画像前処理、プレビュー、閲覧、オフライン保存・同期 |
| クライアント | Webアプリ（SPA） | ドキュメント管理、検索、ログ照会、マスタ管理 |
| クラウド | API Gateway | リクエストルーティング、レート制御、TLS終端 |
| クラウド | 認証/認可サービス | ID/パスワード認証、MFA、SSO（社内IdP連携）、RBAC |
| クラウド | アプリケーションサーバ | ドキュメント/メタデータ/検索/ログのビジネスロジック |
| クラウド | OCR/前処理ワーカー | 画像補正、二値化、OCR、検索可能PDF生成（非同期） |
| クラウド | メタDB（RDB） | ドキュメントメタ・ユーザ・権限・ログの永続化 |
| クラウド | 検索エンジン | OCRテキスト/メタデータの全文索引・あいまい検索 |
| クラウド | オブジェクトストレージ | 非機密ドキュメント本体・サムネイル保存 |
| オンプレ | 機密ストレージ | 機密度の高いドキュメント本体・バックアップ |

### 4.3 技術スタック（想定 / Docker前提）

| 領域 | 候補技術 |
|---|---|
| モバイル | iOS (Swift) / Android (Kotlin)、または React Native / Flutter |
| 撮影・画像処理 | OpenCV（輪郭検出・台形補正・二値化）、端末ネイティブカメラAPI |
| Webフロント | React / TypeScript（SPA） |
| バックエンドAPI | Python (FastAPI) または Node.js、RESTful API |
| OCRエンジン | Tesseract（日本語縦書き含む）または クラウドOCRサービス |
| メタDB | PostgreSQL |
| 検索エンジン | Elasticsearch / OpenSearch |
| ストレージ | クラウド: S3互換オブジェクトストレージ／オンプレ: MinIO等 |
| 認証 | OAuth2 / OIDC（社内IdP連携）、JWTセッション |
| 実行基盤 | Docker / Docker Compose（コンテナ構成） |

### 4.4 処理フロー

#### 撮影〜保存フロー
```
1. ユーザーがモバイルアプリで撮影（複数ページ可）
2. 端末側で輪郭検出・トリミング・傾き/台形補正・画質最適化（F-03〜F-06）
3. 品質チェック（解像度/ピント/明るさ）→低品質なら再撮影を促す（F-09）
4. ページ並べ替え・確認後、サーバへアップロード（オフライン時はローカル保存→再接続時同期 F-11）
5. サーバがOCRワーカーにジョブ投入（非同期）
6. OCR実行→テキスト抽出→検索可能PDF生成（F-13〜F-15）
7. メタデータ付与（F-17）、機密度判定によりオンプレ/クラウドへ保存（F-20）
8. OCRテキストを検索エンジンへインデックス登録（F-23）
```

#### 検索〜閲覧フロー
```
1. ユーザーが全文/キーワード/絞り込み検索を実行（F-23, F-24, F-26）
2. 検索エンジンが索引を照会し結果を返却（ハイライト付き F-25）
3. 権限チェック後、ドキュメントメタとサムネイルを表示（F-21, F-36, F-37）
4. ビューアでページ閲覧（F-22）、権限に応じDL/印刷（F-27）
5. 閲覧・操作ログを自動記録（F-28, F-29）
```

## 5. データモデル

### 5.1 主要エンティティ

#### ドキュメント (documents)
| 項目 | 型 | 備考 |
|---|---|---|
| id | UUID | 主キー |
| title | string | タイトル |
| category_id | FK | カテゴリ |
| document_type | string | 書類種別 |
| page_count | int | ページ数 |
| file_format | string | PDF等 |
| ocr_text | text | OCR抽出テキスト（検索対象） |
| owner_id | FK | 登録者 |
| created_at | datetime | 登録日時 |
| updated_at | datetime | 更新日時 |
| retention_until | date | 保管期限 |
| version | int | バージョン |
| storage_location | enum | onprem / cloud（機密度で決定） |
| sensitivity | enum | 機密度区分 |

#### タグ (tags / document_tags)
ドキュメントと多対多で関連付け（F-39）。

#### 閲覧・操作ログ (access_logs)
| 項目 | 型 | 備考 |
|---|---|---|
| id | UUID | ログID |
| document_id | FK | 対象ドキュメント |
| user_id | FK | 操作者 |
| action | enum | view / download / print / edit / delete |
| operated_at | datetime | 操作日時 |
| device_ip | string | 端末/IP |

> 監査ログは改ざん防止（追記専用・ハッシュチェーン等）を考慮。

#### ユーザー (users)
| 項目 | 型 | 備考 |
|---|---|---|
| id | UUID | ユーザーID |
| name | string | 氏名 |
| department | string | 所属 |
| role | enum | admin / registrar / viewer 等 |
| credentials | - | 認証情報（ハッシュ管理） |

#### 権限 (permissions / acl)
ドキュメント/フォルダ単位のアクセス制御（F-36, F-37）。操作範囲（閲覧のみ/編集可/削除可）を保持。

### 5.2 エンティティ関連（概念）
```
User 1 ──< AccessLog >── 1 Document
User 1 ──< Permission >── 1 Document/Folder
Document >── Category (階層)
Document >──< Tag
Document 1 ──< Version
```

## 6. セキュリティ設計

| 項目 | 方針 |
|---|---|
| 通信 | 全経路 TLS（API Gateway でTLS終端） |
| 保存データ | 保存時暗号化（オンプレ・クラウド両ストレージ） |
| データ配置 | 機密度区分に基づきオンプレ/クラウドへ自動振り分け |
| 認証 | ID/パスワード + MFA、または社内IdPによるSSO（OIDC） |
| 認可 | RBAC + ドキュメント/フォルダ単位ACL |
| 監査ログ | 追記専用・改ざん検知、保持期間を定義 |
| 端末紛失対策 | 原本のローカル非保持を原則、一時データはリモートワイプ可能に |
| コンプライアンス | 個人情報・機密情報の取り扱い方針へ準拠 |
