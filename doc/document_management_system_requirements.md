# 紙媒体資料 撮影・電子保存・閲覧管理システム 要件定義書

## 1. システム概要

スマートフォン/タブレットアプリで紙媒体の資料を撮影し、検索可能なドキュメントとして電子保存し、閲覧記録などを管理するシステム。

- **利用環境**: ハイブリッド構成（オンプレミス + クラウド）
- **重点領域**: OCR・全文検索 / 撮影・画質の使いやすさ

## 3. 非機能要件

### 3.1 性能
- 撮影〜保存（OCR含む）の処理時間目標（例：1ページあたり ○秒以内）
- 全文検索のレスポンス目標（例：○秒以内）
- 想定同時接続ユーザー数・想定ドキュメント総件数の上限定義

### 3.2 セキュリティ
- 通信の暗号化（TLS）、保存データの暗号化
- ハイブリッド構成における機密度別のデータ配置ポリシー
- アクセス制御と監査ログの改ざん防止
- 端末紛失対策（原本のローカル非保持・リモートワイプ等）
- 個人情報・機密情報の取り扱い方針への準拠

### 3.3 可用性・信頼性
- バックアップ・リストア方式（オンプレ/クラウド双方）
- 障害時の復旧目標（RTO/RPO）の定義

### 3.4 運用・保守
- 閲覧ログ・監査ログの保持期間定義
- ストレージ容量の監視・拡張方針
- オンプレ/クラウド間のデータ同期・整合性確保

### 3.5 対応環境
- 対応OS・アプリ（iOS / Android、Webブラウザ）
- オフライン時の一時保存と再接続時同期

## 4. 主要データ項目

### ドキュメント
ID、タイトル、カテゴリ、タグ、書類種別、ページ数、ファイル形式、OCRテキスト、登録者、登録日時、更新日時、保管期限、バージョン、保存先（オンプレ/クラウド）

### 閲覧・操作ログ
ログID、ドキュメントID、ユーザーID、操作種別（閲覧/DL/印刷/編集/削除）、操作日時、端末/IP

### ユーザー
ユーザーID、氏名、所属、ロール、権限、認証情報

## 5. システム構成

### 5.1 技術スタック

| レイヤー | 採用技術 | 役割 |
|---|---|---|
| モバイルアプリ | **Expo（React Native）** ※Development Build | 撮影・補正・閲覧 |
| Webアプリ | **Next.js** | 管理・検索・閲覧 |
| バックエンドAPI | **Django + Django REST Framework** | API・認証・権限・監査ログ・マスタ管理 |
| 非同期処理 | **Celery + Redis** | OCR・画像処理の非同期ジョブ |
| OCR / 画像処理 | **Python（OpenCV / Pillow / Tesseract / PaddleOCR 等）** | 前処理・テキスト抽出 |
| データベース | **PostgreSQL** | メタデータ・ログ・OCRテキスト格納 |
| 全文検索 | **Elasticsearch / OpenSearch** | OCRテキストの全文検索・ハイライト |
| ストレージ | **オブジェクトストレージ** | 機密度に応じクラウド/オンプレへ振り分け |

### 5.2 構成の方針

- バックエンドを **Python（Django）** に統一し、要件の中核である **OCR・画像処理を Python のエコシステム（OpenCV / 各種OCR）で扱える**ことを最大の利点とする。
- Django の管理画面・権限・監査ログ機構を、マスタ管理および監査要件（F-28〜F-41）の基盤として活用する。
- 撮影の輪郭検出・台形補正・品質チェックは Expo 標準APIでは不足するため、**Development Build を前提にネイティブのドキュメントスキャン機能**（react-native-vision-camera / ML Kit / VisionKit 等）を組み込む。
- OCR は同期処理だと重いため **Celery で非同期ジョブ化**し、完了後に検索インデックスへ反映する。
- 全文検索は件数規模・ハイライト要件（F-23, F-25）を踏まえ、**専用検索エンジンを外付け**する。
- **クラウド中心構成**とし、機密度の高い文書のストレージおよびそのOCR処理のみオンプレミスに配置する（ハイブリッド）。

### 5.3 構成図（概念）

```
[Expo App] ──撮影/補正──┐
                        ├─→ [Django + DRF] ──→ [PostgreSQL]
[Next.js Web]─閲覧/検索─┘         │
                                  ├─→ [Celery + Redis] ──→ OCR/画像処理ワーカー
                                  │         ├ 通常文書：クラウドOCR
                                  │         └ 機密文書：オンプレ Tesseract 等
                                  └─→ [Elasticsearch/OpenSearch]（全文検索）
                                            │
                          ストレージ：通常=クラウド / 機密=オンプレ
```

### 5.4 主要な設計上の論点

- **撮影品質**: Expo Development Build でのネイティブスキャン機能の選定・検証。
- **OCRワーカー**: 機密度によるクラウドOCR / オンプレ Tesseract の振り分けロジック。
- **検索エンジン**: 当初規模では PostgreSQL 全文検索（pg_bigm 等）で代替し、規模拡大時に専用エンジンへ移行する段階的選択も可。
- **認証**: 社内IdP連携（SSO / 多要素認証）の方式（F-34）。
